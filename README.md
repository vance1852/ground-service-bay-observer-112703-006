# 相邻检修位的占用归属与工作准入

回放目录使用本地合成设备和事件。约定见 [设备资料](protocol.md)，其中说明实体、事件以及如何解释相应的现场观测。

需要 Python 3.11 标准库。运行 `python3 bench.py` 查看设备与观测数量，运行 `python3 -m unittest discover -s tests -v` 核验判定规则、资料关联和本地 HTTP 往返。用 `python3 bench.py --listen 8765` 启动接入服务，终止进程即可关停。可用 `--scene` 指定同格式的另一份回放；`--catch-up` 启动时先接入全部记录。

## 接入服务

`bench.py` 保留原回放台接口（`/devices`、`/events`、`/commands`），并在同一进程上提供接入服务：

| 接口 | 用途 |
| --- | --- |
| `POST /ingest` | 提交一条观测（字段同 `observations.ndjson` 一行） |
| `POST /ingest/advance` | 按回放顺序接入下一条；`{"count": n}` 接入多条 |
| `POST /ingest/catch-up` | 接入剩余全部回放 |
| `GET /snapshot` | 工位、作业、通知与拒收记录的当前快照 |
| `GET /bays`、`GET /jobs` | 每位状态、每项作业的状态与准入条件 |
| `GET /explain?bay=N` | 该位的完整证据时间线与故障来源 |
| `GET /check?bay=N&type=sweep&unit=...` | 不建单地核对某项工作此刻是否具备条件 |
| `GET /shift` | 当班开工检查：逐位结论、受影响作业、可见故障来源 |
| `POST /commands` | 回放通道收件凭据；不控制真实设备 |

`/commands` 的 202 只表示通道收件，具体动作以随后的设备观测为准。

## 判定约定

- 工位状态为 `occupied`、`empty`、`conflict`、`unknown` 之一。`occupied` 另带 `identified` 与 `unit`，只有结构证据（门侧确认、夹具实际连接、负责人核定的对象）或足够的独立观察才能确认是哪台车。
- 压力只证明占用；近场读头强度没有唯一归属含义，只在同位已有独立占用证据时帮助确认身份，读数接近时保留两个位置的冲突。
- 空位需要空位依据（低压或同一实物确证离位）。低压还需独立的门侧或限定时段人工观察；门侧离位若紧接着读头仍同时报旧位与新位，不释放旧位。
- 迁位同时影响旧位和新位。只有看见同一实物成功离开，等待的任务才能使用旧位；未完成的迁位只记为“可能正在进入”。
- 故障声明只取消对应源从声明时刻起的证明力。旧 `source_epoch` 的观察在更新会话之后补达时只作历史，不能回写现场；同一源较高 `source_epoch` 的新观察解除故障。
- 已确认的占用、冲突或负责人核定结果不会被后来的弱证据清掉。
- 作业：`inspection` 需要该车与同工位接地夹，`sweep` 需要真正空出的区域和已扫除的台面。新申请为 `held`（暂缓），已开工对象在冲突或弱证据不足时 `pending_review`（暂停待复核），在硬矛盾时 `suspended`；弱证据不能退回到更宽松的状态。已开工对象丢失某只传感器时，按剩余证据给出 `continue` / `pause` / `stop`，见作业的 `continuation`。
- 负责人 `site_check` 只覆盖其 `claims` 载明的工位与 `from`–`until` 时间范围。它可以复核受影响的任务和工位，但不能顺手把未载明的故障位改为空闲；负责人的空位凭据晚于旧的结构占用或卡高压力时，可以解除这一冲突，但不会改写它未载明的任何工位。
- 同一工位确认为两台车时保留 `conflict`，不合并；只有看见同一实物离开或确有足够空位证据才释放。门侧看到有车进入或离开但没识别车辆时，不能据此把两台合成一台，也不能据此释放已在位的车。
- 工位与设备都由 `policy.json` / `devices.json` 驱动，新增工位只需补设备能力和邻位关系，无需改判定代码。
